# NPC 个人事件的触发与状态口径

- 日期：2026-11-06（第 65 程）
- 状态：已实施（叙事审计 E2 第一批：陆沉 / 阿砚 / 咕噜）

## 背景

第 24 程叙事审计确认：五名 NPC 的弧光只有静态来历 + 闲聊 + 关键词回应，
没有任何按进度/信任推进的个人事件。剧情圣经为每人写了一个「不愿提的东西」、
一件关键道具与一条弧光，但红色文件夹、玻璃瓶、断尖笔、手绘地图均未实现，
断页剑只作为武器存在。E2 第一批只做 demo 中可见的三名 Hub NPC（陆沉、阿砚、
咕噜）；闻烬与白榆在 `hub.gd` 中不可见，暂不写。

## 决定

1. **事件形态**：每名可见 NPC 一个 Hub 个人事件，走现有 `DialogueUI` 与
   `Hub.talk_to_npc()`；不新增事件 UI、场景、信号或存档系统。事件对白直接
   替换该次交谈的常驻问候/态度/职能行；事件看完后，下一次交谈恢复原样。
2. **触发条件 = 信任档 + 章节进度**：
   - 章节进度用 `Profile.demo_cleared`（完成第 1 章 demo 至少一次）。Hub 在局外，
     `Profile` 没有更细的章节进度；`runs_completed` 含死亡，不作为章节进度。
   - 信任档用既有 `TrustData`（陌生/熟悉/信任/托付，0/2/6/12）。
   - 具体档位：陆沉 `信任`（6）；阿砚 `托付`（12）；咕噜 `熟悉`（2）。理由见
     Session 记录与 `SUPERVISOR_STATUS.md`「NPC 个人事件（第 65 程）」专节。
3. **只触发一次**：事件 id 写入 `Profile.npc_events: Array[String]`（新存档键
   `[npc] events`，旧档缺省为空）。只有读到事件最后一行才记录；中途 B/Esc
   关闭或从事件页打开言灵不消耗事件。记录后不再触发，也不重复发任何东西。
4. **零奖励**：事件不改残页、记忆碎片、信任、祝福、背包、经济、锻造或商店
   数值。剧情圣经中的关键道具（红色文件夹、断页剑、玻璃瓶）只在对话里呈现，
   不新增物品类型/背包条目；道具机制缺口记录在状态文件，留给完整版。
5. **咕噜不跳商店**：普通咕噜对话结束后仍按原逻辑打开货架；个人事件结束后
   不再自动开商店，避免刚说完「这个不卖」就弹货架。
6. **闻烬/白榆不动**：保持不可见，不写事件；两人的个人事件须先拍板
   「是否在 demo 中可见」。

## 后果

- 三名可见 NPC 各有一个一次性 Hub 个人事件，均在第 1 章 demo 通关后可达。
- 不改变第 1 章 9 房间/6 波次/事件/清房目标/结束流程、Hub 闲聊与关键词回应、
  信任数值与存档格式（只新增事件标志位）；第 2–4 章仍不可达。
- 阿砚「叫出真名」的完整分支、结局余味（E3）、闻烬/白榆可见性与事件仍是
  后续程/待拍板项。

## 红线

不新增背包物品类型、不改经济/锻造/商店数值；不改 NPC 立绘；不把闻烬/白榆
设为可见；不开放第 2–4 章可达性、不改章节路由/`CHAPTER_PLAN_PATHS` /
`MDS_WORLD_FILES`；不碰待确认第 11–16 项；不做打包/导出/安装器/签名/安卓/触屏。
