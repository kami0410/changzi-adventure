# 地图标题按章节区域派生

- 日期：2026-11-05（第 38 程）
- 状态：已实施；第 1 章标题冻结，第 2–4 章按同一规则派生

## 背景

`MapOverlay` 的地图标题原本是字面量「档案馆地图」，所有章节共用。第 2 章大图接入后，标题仍显示第 1 章的档案馆名称，与实际区域「呼吸废墟」不一致。需要一个不新造章节名、又不改动第 1 章的派生规则。

## 决定

- 标题从既有 `CampaignData.chapters[i]["region"]` 派生：`"<区域名>地图"`。
- **第 1 章冻结**：`chapter_index <= 0` 恒定返回 `"档案馆地图"`，不跟随 `chapter 0["region"]`（墨雨档案馆）变化。这是为了保持第 1 章既有 UI 文案与测试基线一字不改。
- 第 2–4 章分别得到「呼吸废墟地图」「无光海地图」「笑面剧场地图」。区域为空或索引无效时回落到第 1 章标题，不新造名称。
- `MapOverlay.set_chapter(chapter_index)` 由 `Game._start_mds_chapter()` 在设置世界文件之前调用；`_chapter_index` 会保留，`_build()` 与 `title_text()` 都按它取标题，因此 `_ready()` 之前调用也不会丢。
- 地图世界文件仍由 `set_world()` 单独负责，标题与地图文件是两个独立输入，互不推断。

## 后果

- 第 1 章地图标题保持「档案馆地图」，第 2 章显示「呼吸废墟地图」；单元测试与真实流程测试各锁定一次，并验证章节切换不残留。
- 第 3–4 章即使当前不可达，也自动获得一致标题，不需要再加章节分支。
- 新增章节时只要 `CampaignData` 里有 `region`，地图标题就自动成立；没有 `region` 的章节回落到第 1 章标题。

## 红线

不改第 1 章标题文案；不从章节 `title`/`subtitle` 字符串截取（易随文案改动漂移）；不为地图标题新增存档键或章节数据字段；不改变第 2 章可达性。
