# ADR：MDS 全量接入

## 背景

0.9.0 的结论是“只借气氛”（见 [MDS 调研](../../research/metroidvania-developer-system.md)），
因为直接迁移会触碰 `game.gd` 的章节/检查点/存档。2026-11-02 用户明确要求：
**不再只借气氛，应用 MDS 的全套模式来进化游戏**。3 房间 spike 已证明现有 Player、
Enemy、ArenaRoom、Boss、宝箱、天气都能在 `MDSWorldGame` 里工作（14/14 检查）。

## 决定

1. MDS 成为**章节世界框架**：房间图、门、区域、房间相机、游戏内地图、快速旅行、
   已探索/已击败状态由 MDS 运行时负责。
2. 现有战斗与表现层保留：`Player` / `Enemy` / `ActorMotion` / `CombatFX` /
   `PhraseCaster` / `RelicEffects` / `HUD` 不重写。
3. 采用**逐章迁移**，0.9.2 已四章全部落地：每章 8 房（6 战斗 + 休整 + Boss）`MDSWorldGame`、
   门/相机/天气/地图；旧线性关卡只保留为休眠 fallback。
   见 [MDS 全四章](../../sessions/2026-11-02-mds-migration.md)。
4. 存档与局内进度由现有 `Flow` / `RunState` 继续负责；MDS 只提供世界结构状态，
   不接管 Profile。`defeated_ids` 需要为运行时生成的敌人显式赋 id。
5. 门交互动作改为项目现有 `interact`，不用 MDS 默认的 `ui_up`。

## 约束

- Godot 4.7.2 stable、GL Compatibility、GDScript；不引入 .NET/MetSys 依赖。
- 保留 `ArenaRoom` 类名（避免与 MDS/其他插件的 `Room` 冲突）。
- 编辑器插件资源可以进包；调研已确认按文件夹排除收益小、风险高。
- 迁移期间保持现有 `scenes/main.tscn` 可玩，MDS 章节先在独立场景验证，通过后再切换。
- 验收：现有单测/集成测试全绿；四章可通关；120 FPS 压测不回退；Windows/Android 导出正常。

## 后果

- 收益：可视化房间图、地图/快速旅行、回溯检查、相机适配不规则房间、后续生态区扩展。
- 成本：章节场景与 `game.gd` 的章节位置/检查点/房间注册需要适配层；
  房间内敌人波次仍由现有 `ROOM_WAVES` 生成。
- 风险：插件运行时约定与现有 `CampaignData` 的 12000 px 章节坐标不同；迁移时以
  “一章一世界”而不是“一张 48000 px 大图”，避免坐标与相机限制互相拉扯。
