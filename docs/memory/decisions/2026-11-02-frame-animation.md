# ADR：玩家逐帧动作管线

## 背景

0.9 之前玩家只有一张 96×96 idle，靠 `ActorMotion` 的弹簧压缩、前倾、浮动与围巾模拟动作。试玩里跑步/跳跃/攻击都只有整体变形，缺少可读的腿部与武器姿态。概念图里已有同角色的多个姿势，但直接裁切会带来比例、调色板与 alpha 不一致，且 rembg 抠图残留灰边。

## 决策

1. **动作帧由 Magpie 按动作生成透明底横条**，以 `player_idle.png` 与概念图为参考；每个动作单独一张条，帧间共享角色、服装与比例。
2. **统一用 `tools/slice_anim_sheet.py` 切片与规范化**：按 alpha 列间隙找帧（可合并/切分到目标数）、全组共用一个缩放和 24 色调色板、1 px 墨色描边、脚底基线。横向很宽的挥剑帧用 `--fit height` 和 160×96 画布，避免按宽度缩放把角色缩小。
3. **玩家动作帧仍由 `ActorMotion` 绘制**，不引入 `AnimatedSprite2D`/`SpriteFrames`。`ActorMotion` 每帧按不透明区域的中心与底边锚定，影子宽度固定为 idle 纹理宽度；`Player` 按状态选组、按 `action_progress()` 或 12 fps 计时选帧。
4. **动作状态与帧组绑定**：idle / run（4 帧循环）/ jump-fall（蓄力、上升、下落）/ attack（3 帧）/ cast（2 帧）/ hurt（2 帧）/ dodge（2 帧）。受击闪红、死亡塌缩、残影、落地环仍走现有程序化层。

## 备选

- **Aseprite 手绘整组帧**：质量上限最高，但当前没有逐帧源文件，成本远高于本轮打磨；Aseprite Wizard 仍在项目里，未来可替换。
- **只做程序化骨骼**：无需新资产，但无法表达腿相位和武器伸展，已证明在 96 px 下可读性不足。
- **SpriteFrames + AnimatedSprite2D**：引擎原生，但会把现有 `ActorMotion` 的脚底钉地、挤压、残影和受击闪红拆成两套；改用 `Sprite2D` 纹理切换保留了一层渲染路径。

## 后果

- 正面：跑/跳/攻击/施法有清晰姿态；所有帧共用调色板与基线，切换不闪烁；新增动作只加一条横条和一组 preload。
- 负面：生成帧仍有少量抗锯齿噪点；动作帧数有限（攻击 3 帧、受击 2 帧），快速动作靠程序化挤压补足。正式版应补 Aseprite 中间帧与手工修边。
- 约束：动作帧画布可以大于 96×96（攻击 160×96），但必须保持脚底对齐；`ActorMotion` 不应再假设所有纹理同尺寸。
