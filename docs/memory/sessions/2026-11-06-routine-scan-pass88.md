## 修复）房间奖励页不等待其它页面/过场（与第 86 程延时必选页同一族的最后一处）

**现象。** 击杀房间最后一个敌人后立刻开地图（或暂停、背包），房间仍会在
页面背后清空，延时打开的必选奖励页直接盖在地图上；关地图时
`MapOverlay.close()` 无条件 `get_tree().paused = false`，世界在奖励页仍开着
时恢复。最后一击同帧死亡时同理：死亡归档三选一暂停期间，尸体计时器照走，
房间清空后奖励页会盖在归档页上。

**根因。** 敌人死亡由 `Enemy._queue_free_after_delay()` 的 0.35 s 场景计时器
释放，`SceneTree` 计时器在暂停时继续走；`_on_room_cleared` 在
`_reward_ui.visible` 之前就 `_open_reward.call_deferred()`，而 `_open_reward`
只判 `_finished` / `_ending_pending`，不像事件页（第 86 程
`_ui_blocks_delayed_page()`）和权柄三选一那样等待。探针在真实主场景两种
顺序分别复现「奖励盖地图」与「奖励盖归档页」。

**修复。** `scripts/game.gd`：
- `_open_reward()` 增加等待循环：房间过场（`changing_room`）结束、且
  `_ui_blocks_delayed_page()` 为假才开页；`_death_committed` / `_ended()` 时
  不欠奖励，直接放弃（死亡是终局）。
- 新增 `_reward_pending`：房间结算（`_on_room_cleared`）置真，选择
  （`_on_reward_chosen`）或放弃时置假；`save_run_now()` 在它为真时也返回
  false。原因：等待窗口正好在 `_reward_ui.visible` 之前，暂停/失焦会写检查
  点，而房间已记为清房，续玩会得到「已清房 + 没拿奖励」。
- 未改奖励内容/数值/存档形状/章节路由。

**回归断言。** `tests/integration_run_save.gd` **+15**（660 → 675）：
- 真实 `_on_room_cleared` + 地图开着：奖励等待、`_reward_pending` 挡档、
  关地图后开页、选择前 pending 仍为真（+6）；
- 死亡归档段落改为真实杀波 + 尸体 0.35 s 内死亡：房间清空、归档页仍在、
  奖励不得盖上去（+4）；
- 其余为房间/状态前置断言（+5）。
