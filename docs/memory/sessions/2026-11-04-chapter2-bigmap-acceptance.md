## 发现并修复的真实缺陷

**症状**：从任意 `bot`（地面）门到达后约 0.7 秒，玩家被同一扇门弹回上一房间，导致所有向上纵向连接实际变成单向。

**根因**：`mds_world_game.gd` 对 bot 门到达会把玩家以 `up_exit_speed`（650 px/s）向上抛出门洞；玩家随后落回地面时再次进入同一扇门的触发区。原有的 3 物理帧到达保护 + 0.35 秒门冷却不足以覆盖整个抛物线，门再次触发。

**修复**：在 MDS `mds_world_game.gd` 增加 `floor_arrival_grace`（默认 1.2 秒，`@export` 可关）。仅当到达门在世界上被标记为 `bot` 时，记录该门名与截止时间；宽限期内忽略来自这扇门的触发。横向与 top 到达行为不变；其他章节世界没有 bot 门，不受影响。细节与取舍见 ADR `docs/memory/decisions/2026-11-04-floor-arrival-grace.md`。

**验证**：探针复现修复前 0.8 秒回弹；修复后停留在 `ch2_entry` 3 秒并稳定落地。集成套件用 2 秒窗口断言不回弹。第 1 章不受影响（无 bot 门）。

## 性能基线（headless，Godot 4.7.stable.official.5b4e0cb0f）

以 `fade_time = 0` 测原始构建耗时（正常游戏由 0.22 秒淡入覆盖）：

- 入口 `ch2_entry` 热加载 **9.2 ms**；普通区 **5.6–7.5 ms**。
- Boss 区首次 **61.0 ms**（场景/着色器冷启动），第二次 **10.2 ms**；套件内热加载 **24–43 ms**（多次运行波动）。
- 精英区首次 **35.0 ms**。
- Boss 区关闭动态背景 **11.7 ms**；关闭天气 **9.1 ms**；不生成 Boss **35.9 ms**。

结论：普通区加载远低于一帧预算；首次进入 Boss/精英区的脚本/资源冷启动尖峰被 0.22 秒淡入盖住；动态背景与天气各占数毫秒，未发现需要本程处理的性能缺陷。
