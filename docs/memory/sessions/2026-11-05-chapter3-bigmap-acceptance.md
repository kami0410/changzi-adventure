## 性能基线（headless，Godot 4.7.stable.official.5b4e0cb0f）

原始构建耗时（`fade_time = 0`，正常游戏由 0.22 秒淡入覆盖），两次运行区间：

- 普通区首次：入口 **7.6–8.1 ms**，支路 A **8.4–8.6 ms**，支路 B **9.1–9.2 ms**，枢纽 **7.8 ms**，纵井 **7.4–7.5 ms**，书库 **6.0 ms**，事件 **6.2 ms**，精英 **7.3 ms**。
- Boss 区首次 **41.1–41.4 ms**（场景/立绘/着色器冷启动）；套件内热加载 **24.0–24.4 ms**。
- 普通区热加载 **6.1–7.7 ms**。
- Boss 区关闭动态背景 **5.6–5.8 ms**；关闭天气 **19.8–20.3 ms**；不生成 Boss **12.5–12.8 ms**。
- 真实门过渡（0.22 秒淡入，入口 `right1` → 支路 A）**228–234 ms** 墙钟。

说明：headless 无垂直同步/帧率上限，单帧耗时没有代表性；本作大区按「门 + 淡入」过渡、世界 `seamless_rooms = false`，因此记录门过渡墙钟而不是「无缝切换尖峰」。普通区构建远低于一帧预算；Boss/精英首次尖峰与动态背景开销由 0.22 秒淡入覆盖，未发现需要本程处理的性能缺陷。

## 发现与修复

**未发现产品行为缺陷。** 本程跑通过程中的失败全部在验收脚本自身，属测试写法问题，已就地修正：

1. **HUD 目标断言口径错误**：脚本把 `CampaignData.chapter(2)["objective"]` 当成加载后的 HUD 文本。实际房间加载后由房间类型决定目标（`ch3_entry` 无战斗 → 「休整，或继续前进」），章节目标在进章时即被覆盖。改为断言章节目标已作者化 + 入口房运行时目标。
2. **门冷却内直接开门**：性能段在到达 `ch3_entry` 后立即 `perf_gate.use()`，此时 0.35 秒门冷却未过，`MDSWorldGame._on_gate_entered` 忽略该次触发，门过渡没有开始。与 `_use_gate` 一致，先等 0.45 秒再计时。
3. **延迟 Boss 后续流程抢跑**：性能段用 `_finished`/`_boss_defeated` 抑制「不生成 Boss」测量的后续流程，但 `_on_mds_room_loaded` 的 `_resume_boss_aftermath.call_deferred()` 可能在两个标志复位之后才执行，打开权柄选择页并 `paused = true`，使下一次门过渡的淡入 tween 停住（症状：门过渡 9.4 秒后超时、随后整段挂起）。改为测量期间保持 `_boss_aftermath_started = true`，并在标志复位前多跑两帧让延迟调用先返回。该路径只在测试构造的「Boss 已标记击败但不想跑后续」状态出现；真实流程里 `_boss_defeated` 就该进入后续，不是产品缺陷。
4. **`one_way` 断言读错 API**：`MDSWorld.get_transition()` 只返回运行时目标，不含 `one_way` 元数据。改为读世界门数据断言 `one_way`，并补「到达门无反向转移」断言。
