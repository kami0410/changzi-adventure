## 修复 1）跨章 Boss 检查点续玩会吞掉本章权柄三选一（真实产品行为缺陷）

**现象。** 第 2/3 章 Boss 击败后、权柄选择出现前退出（Boss 死亡检查点已写盘），
下次「继续本局」直接进入章末 outro，本章的权柄三选一不再出现；若玩家身上
带着上一章的权柄，这个检查点会一直跳过本章的授予。

**根因。** `_on_boss_died` 先写 Boss 死亡检查点，再 `await _grant_chapter_authority()`；
`_resume_boss_aftermath()` 只用 `_authority.authority == null` 判断是否补授予。
第 1 章起权柄跨章携带，因此第 2/3 章的检查点里 `authority` 不为空（是上一章
的），续玩被误判为「本章已授予」。探针在真实主场景复现：第 2 章 Boss 房
`boss_defeated=true` + 携带第 1 章 `revive` 的检查点，续玩 2 秒后
`authority_choice_open = false`、outro 直接打开。

**修复。** 新增 `_authority_granted_chapter`（默认 `-1`，表示未授予过）：
`_grant_chapter_authority()` 授予成功时记下 `_chapter`；写入 run save 的
`authority.chapter`；`_restore_authority()` 读回。`_resume_boss_aftermath()`
的补授予条件改为「没有权柄 **或** 当前权柄不是本章授予的」。旧检查点没有
该键时按「文件里保存的章节」解释（`_resume_run_value("chapter", _chapter)`），
保持第 83 程之前的续玩行为——注意恢复发生在 `_ready`，早于
`_start_chapter` 应用章节，不能用运行时的 `_chapter` 兜底。存档只多一个键，
版本/形状校验不需要迁移。

**回归断言。** `tests/integration_run_save.gd` **+26**（631 → 657）：
- 第 2 章 Boss 已授予后写盘，续玩不重开三选一、直接 outro（+2，含
  `authority.chapter = 1` 落盘）；
- 第 2 章 Boss 检查点携带第 1 章权柄（`authority.chapter = 0`）续玩，补开
  本章三选一、选择后授予并进入 outro（+17）；
- 旧形状检查点（无 `authority.chapter` 键）续玩仍视为已授予、不重开（+7）。
