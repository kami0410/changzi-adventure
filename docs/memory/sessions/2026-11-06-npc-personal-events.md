## 圣经依据（原文要点）

来源：`docs/story-bible.md`「四位同行者 / 五位 NPC」。

### 陆沉

- 秘密：「他撕下三页名册，不是为了保护世界，而是为了保护自己不被写进
  『已死之人』那一栏。」
- 弧光：「从『替昌子决定该读什么』到『承认自己也曾篡改』。」
- 关键道具：「红色文件夹，里面是昌子最初的入职档案。」
- 结局后：「如果仁慈足够，他会把红色文件夹交给昌子；否则它会出现在笑面
  剧场的观众席上。」

事件只写「承认」这一刻：他取出红色文件夹、承认撕页是为自保、承认自己一直
替昌子决定该读什么；文件夹没有交给昌子（留给结局）。对白要点：名册
「已死之人」栏里出现他自己的名字；撕掉三页让那一栏少一页；「我还不想被
归档」；文件夹里是昌子最初的入职档案，名字比现在完整；「现在我不想替你
决定了」；「档案长也该被归档一次」。

### 阿砚

- 秘密：「他曾经是旧世界最后一座军械库的锻造之神。世界忘记他的神名后，
  他把自己降格成『守夜人』，因为守夜人不需要被记住。」
- 弧光：「从『拒绝承认神格』到『愿意再为一个人烧一次炉』。」
- 关键道具：「一把永远修不好的断页剑——其实是他给自己留的墓碑。」
- 结局后：「如果昌子叫出他的真名，他会把锤子留在铁砧上，第一次走出
  铁匠铺。」

事件写到「再烧一次炉」为止，不进入真名分支：他先否认剑能修好、承认断页剑
是给自己的碑；说旧世界最后一座军械库是他烧的最后一炉，世界忘记神名后他
改叫阿砚、守夜人不需要名字；昌子的话让他沉默，他在冷炉膛里按了一下，炉底
亮起一线暗红；「只烧这一次。不是给神，也不是给这个世界。是给你。」；
结尾「下次来，别问真名」把真名分支留在以后。

### 咕噜

- 秘密：「它不是这个世界的生物，而是被烧掉的词堆里长出来的『记忆拾荒者』。
  它害怕的不是死，是没人再来买东西。」
- 弧光：「从『什么都卖』到『有一件东西不卖』。」
- 关键道具：「一只装着『永』字的玻璃瓶。」
- 结局后：「如果信任足够，它会把瓶子送给昌子，说『这个不卖，借你』。」

事件写「不卖」的转折：货架最里面压着装着「永」字的玻璃瓶；「那个不卖」；
它承认自己什么都卖、连「永」和「恒」都拆开卖过，但这只瓶子是第一次醒来时
吞下的字；「至少还有一个字，是永远不会被我卖掉的」；最后用玩笑遮住在意：
「别死太早。你死了，谁还来听我讲价？」瓶子没有送出（留给结局）。

## 触发条件与档位理由

| NPC | 事件 id | 信任档 | 门槛 | 章节进度 |
|---|---|---|---|---|
| 陆沉 | `luchen_red_folder` | 信任 | 6.0 | `Profile.demo_cleared` |
| 阿砚 | `ayan_furnace` | 托付 | 12.0 | `Profile.demo_cleared` |
| 咕噜 | `guru_bottle` | 熟悉 | 2.0 | `Profile.demo_cleared` |

- **章节进度用 `demo_cleared`**：Hub 在局外，`Profile` 没有更细的章节进度；
  `demo_cleared` 是唯一「完成过第 1 章 demo」的持久信号，且在 demo 内可达
  （通关 → 结局屏 → 返回 Hub）。`runs_completed` 含死亡，不作为章节进度。
- **陆沉 · 信任（6）**：该档既有态度句「有些页我本来不该给你看。但我想，
  你会替我记住。」正是承认篡改的关系基础；承认自己为自保撕页比日常闲聊重，
  低于托付又显得过早。
- **阿砚 · 托付（12）**：圣经弧光终点是「愿意再为一个人烧一次炉」，该档
  态度句「真名的事……等你准备好，再来问我一次」也把最深的话留在这里；
  再烧炉是「为一个人」，对应最深档。真名分支本程不做。
- **咕噜 · 熟悉（2）**：该档态度句「有些东西我不摆上架，只留给信得过的人」
  直接铺「有一件东西不卖」；这是它弧光的起点，熟悉即可，不需要托付。

## 实现

- 新增 `scripts/hub/npc_event_data.gd`（`NPCEventData`）：三名 NPC 的事件
  id、标题、关键道具名、最低信任档、`requires_demo_cleared` 与对白行；
  `event_for()` 返回副本，`can_trigger(profile, npc_id)` 做一次性 + 档位 +
  章节进度判定。闻烬/白榆/未知 id 无条目。
- `scripts/core/profile.gd`：新增 `npc_events: Array[String]`、
  `has_npc_event()`、`record_npc_event()`（首次返回 true）；存档写
  `[npc] events`，读档缺省为空、跳过空串与重复 id。旧档无需迁移。
- `scripts/hub/hub.gd`：`talk_to_npc()` 先查 `NPCEventData.can_trigger()`；
  可触发时用现有 `DialogueUI` 打开事件对白（替换该次常驻对话），读完最后
  一行才 `_record_npc_event()` 并保存；中途关闭/打开言灵不记录。事件结束后
  咕噜不自动开商店；普通对话仍按原逻辑开商店。事件不改任何数值。
- 关键道具只做叙事节拍：不新增背包物品类型、不改经济/锻造/商店数值。
